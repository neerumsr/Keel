# Files to upload for Keel-Pro (Hugging Face)

Keel-Pro is a LoRA fine-tune of a Qwen3.5 base model (Apache-2.0). It ships as two Hugging Face
repos so that users who only want the GGUF do not pull the adapter tooling, and the reverse:

| HF repo | Contents |
|---|---|
| `neerumsr/keel-pro` | Model card, LoRA adapter (safetensors), tokenizer, `keel-pro.json` (policy + how the adapter was built) |
| `neerumsr/keel-pro-GGUF` | Merged weights as GGUF `Q8_0` and `Q4_K_M`, own card (`hf/keel-pro/GGUF_CARD.md`) |

The finalist run and its base model are recorded in `artifacts/parity/pro/MODEL_CARD.md` and
`artifacts/parity/pro/status.json`. `hf/keel-pro/upload.ps1` defaults `-Run`/`-Base`/`-Gguf` to the release paths; pass others if yours differ.

| Upload path | Source | Approx. size | Notes |
|---|---|---|---|
| `README.md` | `artifacts/parity/pro/MODEL_CARD.md` (adapter repo), `hf/keel-pro/GGUF_CARD.md` (GGUF repo) | 10 KB | No TBD may remain |

Do **not** upload: training data (`training/pro/data/**`), DI dev/report rows or raw outputs,
full bf16 merged checkpoints, optimizer state.

## Steps

1. Resolve the blockers in `RELEASE_CHECKLIST.md` section 3 (Keel-Pro) first.
2. Confirm the MODEL_CARD numbers match `artifacts/parity/pro/di-results.md`.
3. Run `node scripts/oss-audit.mjs --fail-on medium`.
4. `hf auth login`, then from the repo root: `pwsh hf/keel-pro/upload.ps1` (repos are created **private**; add `-Public`,
   or flip visibility on the Hub, at launch). Rerunning is safe: unchanged files are skipped.
