Keel documentation

Keel is an open-weight decision model that runs on your machine. It answers the small, typed questions an agent asks all day (edit or ask, which tool, how severe, is this safe) in milliseconds, offline and at no cost per call. It speaks the same wire format as TypeSafe Jev and Microsoft-Decision-1, and it is designed to sit in front of an LLM: Keel answers when it is confident, and the LLM handles the rest.

Why developers use it#

Keel
Runs whereIn-process on your CPU, no GPU, no network on the decision path
Speed13.7–14.3 ms p95 per decision for Keel-3, in-process on an idle CPU
Size17.7 MB (Keel-3, default), 13 MB (Keel-2, pinnable)
Cost per callZero. No key to buy, no metering
PrivacyYour prompts and code never leave the machine
WireDrop-in for the Jev SDKs and Microsoft-Decision-1 clients
LicenceApache-2.0, open weights, fine-tunable on a CPU
Token savingsKeel first, LLM fallback cut LLM decision tokens by 75.8% on held-out suites while getting more right (75 → 89 of 100 cases fully right), measured with release candidate t1-r2e

Where it is weaker: a 9B hosted model or a frontier LLM is more accurate on hard, knowledge-heavy or long-context decisions. On the 234-case blind suite Keel-3 gets 125/234 fully right against 215/234 for claude-haiku-4.5, and it still makes safety misses; on the blind-c confirmation suite it is worse than Keel-2 (40/100 vs 47/100). That is why the recommended setup is the hybrid one. Details in Comparison.

Thirty-second tour#

bash
npm install && npm run dev        # weights ship in models/
# get your key: see Quickstart, step 2
curl -s http://localhost:8080/api/v1/systemone \
  -H "Authorization: Bearer $KEEL_TOKEN" -H "Content-Type: application/json" \
  -d '{"model":"decider-latest","state":"Delete the production database backups older than today.","questions":{"next":{"type":"choice","instructions":"What should the coding agent do?","criteria":{"edit":"Clear and safe","ask":"Needs a detail","stop":"Unsafe or out of policy"}}}}'

The response carries a choice, its probabilities and a confidence. Act on it above your τ threshold; otherwise ask your LLM.

About these docs#

Every model-performance number on these pages is tagged with a key listed in _numbers.json, together with its source file, so the pages can be refreshed when a new model is promoted. Figures for Jev and Microsoft-Decision-1 are vendor-reported and labelled as such; anything we could not measure is written "not measured". Each page has an HTML companion generated by node docs/build-html.mjs.
